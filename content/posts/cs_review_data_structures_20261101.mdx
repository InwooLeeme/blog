오늘은 『면접을 위한 CS 전공지식 노트』 5장 자료 구조를 읽고, Claude가 만든 객관식 퀴즈로 내용을 복습했다. 복잡도부터 배열과 연결 리스트, 그래프와 트리, 힙과 해시 테이블까지 다뤘다.

복습은 세 차례 진행했다. 첫 번째 퀴즈 15문항에서는 배열의 중간 삽입·삭제와 정 이진 트리 문제를 틀렸다. 빠진 범위와 틀린 개념을 보충하는 12문항을 더 풀었고, 마지막 퀴즈에서는 20문항 중 18문항을 맞혔다. 마지막에 틀린 두 문제는 그래프의 최대 간선 수와 트리의 부모 관계였다.

이번 글은 퀴즈와 해설을 바탕으로 개념을 다시 연결한 기록이다. **연산이 빠르다는 설명에는 어떤 조건이 붙는지, 비슷한 구조를 구분하는 조건은 무엇인지**를 중심으로 정리했다.

## 1. 복잡도: 어떤 연산을 비교하는가

시간 복잡도는 입력 크기가 커질 때 필요한 연산량이 어떻게 증가하는지 나타낸다. 실행 시간을 초 단위로 예측하기보다는, 입력 크기에 따른 증가 양상을 비교하는 기준이다.

| 표기 | 의미 |
| --- | --- |
| 빅오 $O$ | 점근적 상한 |
| 빅오메가 $\Omega$ | 점근적 하한 |
| 빅세타 $\Theta$ | 점근적 상한과 하한이 같은 차수인 경우 |

예를 들어 연산량이 $3n^2 + 2n + 1$이라면 최고차항을 기준으로 $\Theta(n^2)$라고 표현할 수 있고, $O(n^2)$도 성립한다. 빅오 자체가 최악의 경우를 뜻하는 것은 아니다. 최악·평균 중 어떤 경우의 연산량을 분석하는지와 그 연산량에 어떤 점근 표기를 쓰는지는 구분해야 한다.

### 반복문이 두 개라고 항상 같은 비용은 아니다

퀴즈에 다음과 같은 코드가 나왔다.

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = 0; j < i; ++j) {
        ++cnt;
    }
}
```

안쪽 반복 횟수는 바깥쪽의 `i`에 따라 달라진다. 전체 실행 횟수를 더하면 다음과 같다.

$$
0 + 1 + \cdots + (n - 1) = \frac{n(n - 1)}{2}
$$

따라서 시간 복잡도는 $\Theta(n^2)$다. 반복문 개수를 세기보다 **각 반복이 실제로 몇 번 실행되는지**를 확인해야 한다.

공간 복잡도는 실행에 필요한 메모리 양을 입력 크기에 따라 분석한다. 배열이나 동적 할당 메모리뿐 아니라 재귀 호출의 스택 프레임도 고려한다. 입력 저장 공간까지 포함하는지, 추가로 사용하는 보조 공간만 계산하는지도 구분해야 한다.

메모이제이션은 이미 계산한 결과를 저장해 재계산을 줄인다. 계산 결과를 저장할 공간을 더 사용해 시간을 줄이는 예다.

## 2. 배열과 연결 리스트: 위치를 찾는 비용까지 보기

첫 퀴즈에서 틀린 문제 중 하나는 배열과 연결 리스트의 비교였다. 옳지 않은 설명을 고르는 문제였고, 정답은 **“배열은 중간 삽입·삭제가 $O(1)$이다”**였다.

배열은 원소가 연속된 메모리에 놓여 있어 인덱스로 바로 접근할 수 있다. 하지만 중간에 원소를 넣거나 순서를 유지하며 삭제하려면 뒤의 원소를 이동해야 한다.

연결 리스트는 노드가 다음 노드 등을 가리키는 구조다. 인덱스만으로 바로 접근할 수 없으므로 원하는 위치까지 링크를 따라가야 한다.

| 연산 | 배열 | 연결 리스트 |
| --- | --- | --- |
| 인덱스로 원소 접근 | $O(1)$ | $O(n)$ |
| 정렬되지 않은 값 탐색 | $O(n)$ | $O(n)$ |
| 중간 삽입·삭제 | 원소 이동 때문에 $O(n)$ | 필요한 노드 참조를 확보했다면 링크 변경은 $O(1)$ |

여기서 **“필요한 노드 참조를 확보했다면”**이라는 전제가 중요하다.

단일 연결 리스트에서 일반적으로 특정 노드를 삭제하려면 이전 노드를 알아야 한다. 이전 노드를 찾는 과정이 필요하다면 $O(n)$이 걸릴 수 있다. 반면 이중 연결 리스트는 이전·다음 노드 참조를 모두 가지므로, 삭제할 노드가 주어지면 링크를 바꾸는 작업은 $O(1)$이다.

| 종류 | 연결 방식 |
| --- | --- |
| 단일 연결 리스트 | 다음 노드를 가리키는 `next` |
| 이중 연결 리스트 | 이전·다음 노드를 가리키는 `prev`, `next` |
| 원형 연결 리스트 | 마지막 노드가 다시 첫 노드로 연결됨 |

따라서 “삽입·삭제가 많으면 연결 리스트”라는 설명만으로는 부족하다. 매번 위치를 탐색해야 하는지, 이미 노드를 가리키는 참조를 가지고 있는지까지 봐야 한다.

### 벡터의 맨 뒤 삽입은 왜 분할 상환 상수 시간일까?

C++의 `vector`는 크기를 바꿀 수 있는 동적 배열이다. 인덱스 접근은 $O(1)$이고, 중간 삽입·삭제는 원소를 이동하므로 $O(n)$이다.

맨 뒤에 추가할 여유 용량이 있으면 원소 하나를 넣으면 된다. 용량이 부족하면 새 메모리를 확보하고 기존 원소를 옮겨야 하므로 해당 삽입은 $O(n)$이 될 수 있다.

다만 여유 용량을 확보하며 늘리기 때문에, 여러 번의 삽입에 든 비용을 나누면 `push_back`은 **분할 상환 $O(1)$**이다. 모든 호출이 각각 $O(1)$이라는 뜻은 아니다. 용량을 정확히 두 배로 늘린다는 규칙도 C++ 표준의 보장은 아니다. [C++ 표준 초안: vector](https://eel.is/c++draft/vector.overview), [삽입 연산](https://eel.is/c++draft/vector.modifiers)

## 3. 스택과 큐: 어떤 원소가 먼저 나오는가

스택은 나중에 들어온 원소가 먼저 나오는 LIFO, 큐는 먼저 들어온 원소가 먼저 나오는 FIFO 구조다.

같은 연산을 적용하면 차이가 분명해진다.

```text
1, 2, 3 삽입 → 하나 꺼내기 → 4 삽입 → 하나 꺼내기 → 하나 꺼내기

스택: 3, 4, 2 순서로 나옴 / 1이 남음
큐:   1, 2, 3 순서로 나옴 / 4가 남음
```

스택은 재귀 호출의 실행 상태 관리나 실행 취소처럼 최근 작업을 먼저 되돌리는 상황에, 큐는 BFS처럼 먼저 들어온 대상을 먼저 처리하는 상황에 사용한다.

일반적인 구현에서 삽입·제거는 상수 시간이며, 동적 배열을 사용하는 경우에는 재할당에 따른 분할 상환 비용을 구분한다. C++의 `stack`과 `queue`는 임의 원소를 탐색하는 인터페이스를 제공하지 않는다.

## 4. 그래프와 트리: 간선 수의 조건 구분하기

마지막 퀴즈에서 틀린 두 문제는 그래프와 트리의 관계를 묻는 문제였다. 하나는 무방향 단순 그래프의 최대 간선 수, 다른 하나는 트리에서 한 노드가 여러 부모를 가질 수 있는지였다.

### 그래프의 최대 간선 수와 트리의 간선 수

그래프는 정점과 간선으로 이뤄진다. 방향 그래프에서는 정점으로 들어오는 간선 수를 진입 차수, 나가는 간선 수를 진출 차수라고 한다.

예를 들어 `A → B`, `A → C`, `C → A`, `B → C`가 있으면 A의 진입 차수는 1, 진출 차수는 2다.

자기 루프와 중복 간선이 없는 경우, 정점 수 $V$에 따른 간선 수는 다음과 같다.

| 구조 | 간선 수 | 이유 |
| --- | --- | --- |
| 무방향 단순 그래프 | 최대 $V(V-1)/2$ | 서로 다른 정점 쌍마다 간선 하나 |
| 방향 단순 그래프 | 최대 $V(V-1)$ | 서로 다른 정점의 순서쌍마다 간선 하나 |
| 트리 | 정확히 $V-1$ | 연결되어 있고 사이클이 없음 |

무방향 그래프에서는 A–B와 B–A가 같은 간선이다. 방향 그래프에서는 A→B와 B→A를 각각 둘 수 있다.

**$V-1$은 정점이 $V$개인 연결 그래프를 만드는 데 필요한 최소 간선 수이자 트리의 간선 수다.** 일반 그래프의 최대 간선 수와는 다르다. 여기서는 정점이 하나 이상인 경우를 다룬다.

### 트리에서 부모가 하나인 이유

무방향 트리는 사이클이 없는 연결 그래프다. 임의의 두 정점 사이에 단순 경로가 정확히 하나 존재한다.

여기에 루트를 정하면 루트 쪽으로 이어지는 이웃을 부모, 반대쪽 이웃을 자식으로 구분할 수 있다. 루트에는 부모가 없고, 나머지 노드에는 부모가 정확히 하나 있다. 루트에서 같은 노드까지 서로 다른 두 경로가 생긴다면 트리의 경로 유일성에 어긋난다.

| 용어 | 의미 |
| --- | --- |
| 루트 | 기준으로 정한 노드, 부모가 없음 |
| 리프 | 자식이 없는 노드 |
| 노드의 깊이 | 루트에서 해당 노드까지의 간선 수 |
| 트리의 높이 | 모든 노드 깊이의 최댓값 |

이 글에서는 간선 수로 깊이와 높이를 센다. 따라서 루트의 깊이와 노드 하나인 트리의 높이는 0이다.

## 5. 이진 트리: 정·완전·포화를 구분하기

첫 퀴즈에서는 **모든 노드의 자식이 0개 또는 2개인 트리**를 묻는 문제도 틀렸다. 정답은 정 이진 트리다.

| 종류 | 구분하는 조건 |
| --- | --- |
| 정 이진 트리(full) | 모든 노드의 자식 수가 0 또는 2 |
| 완전 이진 트리(complete) | 마지막 레벨 전까지 모두 차 있고, 마지막 레벨은 왼쪽부터 채움 |
| 포화 이진 트리(perfect) | 모든 레벨이 가득 참 |
| 변질 이진 트리(degenerate) | 각 내부 노드가 자식을 하나만 가져 선형으로 이어짐 |

아래 트리는 완전 이진 트리지만 정 이진 트리는 아니다.

```text
      A
     / \
    B   C
   /
  D
```

마지막 레벨이 왼쪽부터 채워져 있으므로 완전 이진 트리다. 하지만 B의 자식이 하나뿐이므로 정 이진 트리는 아니다.

포화 이진 트리는 정 이진 트리이면서 완전 이진 트리다. 반대로 정 이진 트리라는 조건만으로, 또는 완전 이진 트리라는 조건만으로 포화라고 판단할 수는 없다.

높이가 $h$인 포화 이진 트리는 깊이 $k$에 노드가 $2^k$개씩 있다. 전체 노드 수와 리프 수는 다음과 같다.

$$
\text{전체 노드 수} = \sum_{k=0}^{h} 2^k = 2^{h+1}-1,
\qquad \text{리프 수} = 2^h
$$

### 이진 탐색 트리에서 균형이 필요한 이유

중복 키가 없다고 할 때 이진 탐색 트리(BST)는 각 노드의 왼쪽 서브트리에 더 작은 키, 오른쪽 서브트리에 더 큰 키를 둔다. 중위 순회하면 키가 오름차순으로 나온다.

탐색 비용은 트리 높이에 비례한다. 균형이 잡혀 있으면 $O(\log n)$이지만, 정렬된 키를 순서대로 삽입해 한쪽으로 치우치면 최악 $O(n)$이 된다. 평균 $O(\log n)$이라는 설명에도 삽입 순서 등에 대한 가정이 필요하다.

AVL 트리와 레드 블랙 트리는 서로 다른 규칙으로 높이를 $O(\log n)$으로 유지한다.

| 구분 | AVL 트리 | 레드 블랙 트리 |
| --- | --- | --- |
| 균형 조건 | 각 노드의 좌우 서브트리 높이 차가 1 이하 | 노드 색과 검정 높이에 관한 규칙 |
| 복구 방법 | 회전 | 재색칠과 회전 |
| 탐색·삽입·삭제 | 최악 $O(\log n)$ | 최악 $O(\log n)$ |

레드 블랙 트리는 루트와 NIL 리프를 검정으로 두고, 빨간 노드의 자식은 검정이어야 하며, 각 노드에서 하위 NIL 리프까지 가는 경로의 검정 노드 수를 같게 유지한다. 삽입할 새 내부 노드는 보통 빨강으로 두고, 규칙 위반을 수정한다. 삭제 때도 별도의 균형 복구가 필요하다.

“좌우 높이 차가 1 이하”는 AVL의 조건으로 구분해 기억해야 한다. 균형 트리마다 균형을 유지하는 규칙이 다르다. [NIST: 균형 트리](https://xlinux.nist.gov/dads/HTML/balancedtree.html)

## 6. 힙과 우선순위 큐: 전체 정렬 없이 최댓값 꺼내기

이진 힙은 완전 이진 트리 형태를 유지하면서 부모와 자식 사이의 대소 관계를 보장한다. 최대 힙에서는 부모가 자식보다 크거나 같다.

완전 이진 트리는 빈칸 없이 배열로 표현할 수 있다. 인덱스에 따른 관계는 다음과 같다.

| 인덱스 시작 | 왼쪽 자식 | 오른쪽 자식 | 부모 |
| --- | --- | --- | --- |
| 1 | $2i$ | $2i+1$ | $\lfloor i/2 \rfloor$ |
| 0 | $2i+1$ | $2i+2$ | $\lfloor (i-1)/2 \rfloor$ |

부모 식은 루트가 아닌 노드에 적용한다.

최대 힙에 삽입할 때는 마지막 위치에 원소를 넣고, 부모보다 크면 위로 올린다. 최댓값을 제거할 때는 마지막 원소를 루트로 옮긴 뒤, 자식과 비교하며 아래로 내린다. 높이가 $O(\log n)$이므로 두 작업 모두 $O(\log n)$이다.

힙으로 구현한 우선순위 큐는 최우선 원소 확인이 $O(1)$, 삽입·제거가 $O(\log n)$이다. 우선순위 큐는 동작을 나타내는 추상 자료형이고, 힙은 이를 구현하는 방법 중 하나다.

**힙은 전체가 정렬된 구조가 아니다.** 부모와 자식의 관계는 보장하지만 형제끼리의 순서까지 정하지는 않으므로, 임의의 값을 찾는 작업은 최악 $O(n)$이다.

## 7. 맵·셋과 해시 테이블: 정렬과 탐색 비용 비교하기

맵은 키와 값을 연결하고, 셋은 키 자체를 저장한다. C++에서는 정렬된 컨테이너와 해시 기반 컨테이너를 구분해서 볼 수 있다.

| 구분 | `map` / `set` | `unordered_map` / `unordered_set` |
| --- | --- | --- |
| 순회 순서 | 비교 기준에 따라 키가 정렬됨 | 정렬 순서 보장 없음 |
| 키 탐색 | $O(\log n)$ | 평균 $O(1)$, 최악 $O(n)$ |
| 단일 원소 삽입 | 일반적으로 $O(\log n)$ | 평균 $O(1)$, 최악 $O(n)$ |
| 중복 키 | 허용하지 않음 | 허용하지 않음 |

`map`과 `set`은 보통 레드 블랙 트리로 구현되지만, C++ 표준이 특정 트리 구현을 강제하는 것은 아니다. 정렬 관계와 연산 복잡도 등의 요구사항을 보장한다. 중복 키를 허용하는 별도 컨테이너로는 `multimap`, `multiset` 등이 있다. [C++ 표준 초안: 연관 컨테이너](https://eel.is/c++draft/associative.reqmts)

해시 테이블은 해시 함수로 키를 저장 위치에 대응시킨다. 서로 다른 키가 같은 위치에 대응하는 충돌은 같은 버킷에 원소들을 모으는 체이닝이나 다른 빈 위치를 찾는 개방 주소법 등으로 처리한다.

적재율이 높아지면 테이블을 확장하고 원소를 다시 배치할 수 있다. 해시 기반 컨테이너를 사용할 때도 **평균 상수 시간과 최악 선형 시간을 구분**해야 한다. [C++ 표준 초안: 비정렬 연관 컨테이너](https://eel.is/c++draft/unord.req)

## 8. 퀴즈에서 다시 확인한 네 가지

대화 기록에는 틀린 문제 번호가 남아 있지만, 내가 실제로 고른 선지는 남아 있지 않다. 어떤 오답을 골랐는지 추측하기보다 해당 문제에서 구분해야 했던 기준을 정리했다.

| 틀린 문제의 주제 | 다시 정리한 기준 |
| --- | --- |
| 배열과 연결 리스트 | 배열의 인덱스 접근은 $O(1)$이지만 중간 삽입·삭제는 $O(n)$이다. 연결 리스트의 링크 변경 비용에는 위치 확보 조건이 붙는다. |
| 정 이진 트리 | 자식 수가 0 또는 2인지 본다. 완전은 채우는 위치, 포화는 모든 레벨이 찼는지를 본다. |
| 무방향 단순 그래프의 최대 간선 수 | 서로 다른 정점 쌍의 수인 $V(V-1)/2$다. 트리의 $V-1$과 구분한다. |
| 트리의 부모 관계 | 루트를 정한 트리에서 루트 외 노드의 부모는 정확히 하나다. 두 정점 사이 단순 경로도 유일하다. |

첫 퀴즈 이후에는 연결 리스트의 종류, 점근 표기법, 그래프의 차수, 우선순위 큐와 셋 등도 보충했다. 두 번째 퀴즈의 채점 결과는 기록에 없으므로, 마지막 퀴즈의 18/20 결과와 구분해 두었다.

이번 복습에서 다시 짚은 부분은 **자료 구조의 연산 비용에 붙는 전제와 구조를 정의하는 조건**이었다. “삽입이 빠르다”면 위치를 찾는 비용이 포함됐는지, “트리다”라면 연결성과 사이클 조건을 만족하는지까지 함께 설명해야 한다.
