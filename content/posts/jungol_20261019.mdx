## 예시 코드에서 사용하는 템플릿

공통 헤더와 `Main()`, `main()`은 생략했다. 아래 코드 블록은 각각 독립된 문제의 `solve()`이며, 하나씩 템플릿에 넣으면 된다. `Main()`의 테스트 케이스 수는 기본값인 `t = 1`로 둔다.

- 입출력: `ri`, `po`
- 자료형: `vi`, `vl`, `vvi`, `vvl`, `pii`, `ti3`, `vs`
- 반복과 갱신: `F0R`, `FOR`, `each`, `all`, `chmin`, `chmax`
- 격자 이동: `bound`, `dx`, `dy`, `knx`, `kny`
- 비용의 초기값: `iinf`

템플릿의 `inf = 1 << 31`은 32비트 `int`에서 양수 무한대로 사용할 수 없다. 최소 비용을 저장하는 예시에서는 `ll`과 `iinf = 1LL << 60`을 사용한다. GNU 확장 헤더를 포함한 템플릿이므로 GNU C++20 환경을 기준으로 한다.

## 1. 1681 — 해밀턴 순환회로

[문제 원문](https://jungol.co.kr/problem/1681)

1번 장소에서 출발해 모든 장소를 정확히 한 번씩 방문한 뒤 돌아오는 최소 비용을 구한다. 장소 수는 최대 13개다. 비용 행렬은 방향을 가지며, **0은 무료 이동이 아니라 이동 불가**를 뜻한다.

### 방문 순서 대신 방문 집합을 기억하기

방문 순서를 모두 나열하면 팩토리얼 크기의 탐색이 된다. 그런데 이미 방문한 장소 집합과 현재 위치가 같다면, 앞으로 방문할 수 있는 장소도 같다. 이 상태에 더 비싸게 도착한 경로는 버려도 된다.

`dp[mask][u]`를 다음과 같이 정의한다.

> 1번에서 출발해 `mask`에 표시된 장소를 방문하고, `u`에서 끝나는 경로의 최소 비용.

코드에서는 장소 번호를 0부터 센다. 시작 상태는 `dp[1][0] = 0`이다. 아직 방문하지 않은 `v`로 가는 간선이 있으면 다음 상태를 갱신한다.

$$
dp[mask \cup \{v\}][v]
= \min(dp[mask \cup \{v\}][v],\ dp[mask][u] + cost[u][v])
$$

마지막에는 모든 장소를 방문한 상태에서 **출발지로 돌아오는 비용까지** 더해야 한다. 마지막 장소에 도착하는 비용만 비교하면 순환회로가 완성되지 않는다.

```cpp showLineNumbers
void solve(){
    int n; ri(n);
    vvi a(n, vi(n)); ri(a);
    if(n == 1){ po(0); return; }

    int full = (1 << n) - 1;
    vvl dp(1 << n, vl(n, iinf));
    dp[1][0] = 0;

    FOR(mask, 1, 1 << n){
        F0R(u, n){
            if(dp[mask][u] == iinf) continue;
            F0R(v, n){
                if((mask & (1 << v)) || a[u][v] == 0) continue;
                chmin(dp[mask | (1 << v)][v], dp[mask][u] + a[u][v]);
            }
        }
    }

    ll res = iinf;
    FOR(u, 1, n){
        if(a[u][0] == 0 || dp[full][u] == iinf) continue;
        chmin(res, dp[full][u] + a[u][0]);
    }
    po(res == iinf ? -1 : res);
}
```

시간 복잡도는 $O(2^N N^2)$, 공간 복잡도는 $O(2^N N)$이다. `N = 13`이면 상태 배열은 약 10만 개의 값을 저장한다.

원문 예제는 `1 → 4 → 5 → 2 → 3 → 1`로 이동하면 비용이 `30`이다. 원문에는 순환회로가 없는 경우의 출력이 명시되어 있지 않다. 예시 코드의 `-1`은 그 경우를 구분하기 위한 자체 처리이며, 공식 출력 규칙으로 해석하면 안 된다. 장소가 하나라면 이동하지 않는 비용 `0`으로 처리했다.

## 2. 1106 — 장기

[문제 원문](https://jungol.co.kr/problem/1106)

장기판에서 말을 움직여 졸이 있는 칸까지 가는 최소 이동 횟수를 구한다. 판의 행과 열은 각각 최대 100이다. 이동은 행·열 변화량이 `(1, 2)` 또는 `(2, 1)`인 여덟 방향으로, 템플릿의 `knx`, `kny`를 그대로 사용할 수 있다.

### 모든 이동 비용이 1이면 BFS

한 번 이동하는 비용이 항상 같으므로, 시작점에서 가까운 칸부터 큐로 탐색한다. 처음 발견한 칸의 거리는 바로 최단 거리다.

`dist`를 `-1`로 초기화하면 방문 여부와 거리를 함께 관리할 수 있다. 방문 표시는 큐에서 꺼낼 때가 아니라 **큐에 넣을 때** 한다. 그래야 같은 칸이 여러 경로에서 중복으로 들어가지 않는다.

```cpp showLineNumbers
void solve(){
    int n, m, r, c, s, k;
    ri(n, m, r, c, s, k);
    --r; --c; --s; --k;

    vvi dist(n, vi(m, -1));
    queue<pii> q;
    dist[r][c] = 0;
    q.push({r, c});

    while(!q.empty()){
        auto [x, y] = q.front(); q.pop();
        if(x == s && y == k) break;
        F0R(d, 8){
            int nx = x + knx[d], ny = y + kny[d];
            if(!bound(nx, ny, n, m) || dist[nx][ny] != -1) continue;
            dist[nx][ny] = dist[x][y] + 1;
            q.push({nx, ny});
        }
    }
    po(dist[s][k]);
}
```

시간과 공간 복잡도는 모두 $O(NM)$이다. 입력 좌표는 1부터 시작하므로 코드에서는 1을 빼서 사용한다. 원문 예제의 답은 `2`다.

시작점과 도착점이 같으면 답은 `0`이다. 매우 좁은 판에서는 도달할 수 없는 칸도 생긴다. 원문은 도달 불가능한 경우의 출력값을 명시하지 않으므로, 코드에 남는 `-1` 역시 예시의 자체 처리다.

## 3. 1008 — 경로찾기

[문제 원문](https://jungol.co.kr/problem/1008)

격자에서 일사량의 합을 최소화하며 이동하되, 식당이 닫히기 전인 `t`분 이내에 도착해야 한다. 한 칸 이동에는 1분이 걸린다. `0`은 건물, `-1`은 출발점, `-2`는 도착점이며 나머지 양수가 일사량이다. 격자 한 변은 최대 100, 제한 시간은 최대 5,000이다.

### 같은 칸이라도 도착 시간이 다르면 다른 상태

BFS로 가장 빨리 도착하는 길을 찾는 것만으로는 부족하다. 조금 돌아가더라도 햇빛을 덜 받는 길이 더 좋을 수 있다. 반대로 일사량만 최소화하면 시간 제한을 넘길 수 있다.

어떤 칸에 다음 두 경로로 도착했다고 생각해 보자.

- 3분, 일사량 10
- 5분, 일사량 4

두 번째 경로가 저렴하지만 남은 시간이 짧다. 목적지까지 2분이 더 필요하고 제한이 6분이면 첫 번째 경로만 사용할 수 있다. 따라서 위치별 최소 비용 하나만 저장하면 필요한 경로를 놓칠 수 있다.

`dp[k][v]`를 **정확히 `k`번 이동해서 `v`에 도착하는 최소 일사량**으로 정의한다. `k`번째 층의 값만으로 `k + 1`번째 층을 만들면 되므로 배열은 두 개만 필요하다.

```cpp showLineNumbers
void solve(){
    int n, t; ri(n, t);
    vvi a(n, vi(n)); ri(a);
    int sz = n * n, st = -1, en = -1;
    vi cost(sz);
    vvi adj(sz);

    F0R(x, n) F0R(y, n){
        int u = x * n + y;
        if(a[x][y] == -1) st = u;
        if(a[x][y] == -2) en = u;
        cost[u] = max(a[x][y], 0);
        if(a[x][y] == 0) continue;
        F0R(d, 4){
            int nx = x + dx[d], ny = y + dy[d];
            if(bound(nx, ny, n, n) && a[nx][ny] != 0)
                adj[u].pb(nx * n + ny);
        }
    }

    // 비용이 음수가 아니므로 사이클 없는 최적 경로를 선택할 수 있다.
    t = min(t, sz - 1);
    vl cur(sz, iinf), nxt(sz, iinf);
    cur[st] = 0;
    ll res = iinf;

    FOR(step, 1, t + 1){
        fill(all(nxt), iinf);
        F0R(u, sz){
            if(cur[u] == iinf || u == en) continue;
            each(v, adj[u]) chmin(nxt[v], cur[u] + cost[v]);
        }
        chmin(res, nxt[en]);
        cur.swap(nxt);
    }
    po(res == iinf ? -1 : res);
}
```

출발점과 도착점의 비용은 `0`으로 두고, 다음 칸에 들어갈 때 그 칸의 일사량을 더한다. 도착한 경로는 더 확장하지 않는다. 이미 목적지에 왔는데 다시 나갈 이유가 없기 때문이다.

주의할 점은 **정확히 `t`번 이동한 결과가 아니라 1번부터 `t`번까지의 도착 비용 중 최솟값**을 구한다는 것이다. 그래서 매 단계의 `nxt[en]`을 `res`에 반영한다. 현재 층과 다음 층을 같은 배열에서 갱신하면 한 단계 안에 여러 번 이동할 수 있으므로 배열도 분리해야 한다.

시간 복잡도는 $O(tN^2)$, 공간 복잡도는 $O(N^2)$이다. 음수 비용이 없어 경로에서 사이클을 제거해도 비용과 시간이 증가하지 않으므로, 이동 횟수의 상한을 `N² - 1`로 줄여도 된다. 원문 예제의 답은 `15`다.

## 4. 1131 — 위성사진

[문제 원문](https://jungol.co.kr/problem/1131)

사진에서 `*`는 목장, `.`은 빈 칸이다. 상하좌우로 연결된 목장 중 가장 큰 영역의 칸 수를 구한다. 대각선으로 닿은 칸은 같은 영역이 아니다.

### 한 번의 BFS가 한 영역을 센다

사진을 순회하다가 아직 방문하지 않은 `*`를 만나면 BFS를 시작한다. 연결된 목장을 전부 방문하면서 크기를 세고, 지금까지의 최댓값과 비교한다.

방문한 `*`를 `.`으로 바꾸면 별도의 방문 배열 없이도 구현할 수 있다. 원본 사진을 나중에 다시 사용할 필요가 없으므로 가능한 방식이다.

```cpp showLineNumbers
void solve(){
    int w, h; ri(w, h);
    vs a(h); ri(a);
    int res = 0;

    F0R(r, h) F0R(c, w){
        if(a[r][c] != '*') continue;
        queue<pii> q;
        q.push({r, c});
        a[r][c] = '.';
        int cnt = 0;

        while(!q.empty()){
            auto [x, y] = q.front(); q.pop();
            ++cnt;
            F0R(d, 4){
                int nx = x + dx[d], ny = y + dy[d];
                if(!bound(nx, ny, h, w) || a[nx][ny] != '*') continue;
                a[nx][ny] = '.';
                q.push({nx, ny});
            }
        }
        chmax(res, cnt);
    }
    po(res);
}
```

입력 순서는 **가로 `W`, 세로 `H`**다. 배열은 `H`행 `W`열로 만들어야 한다. 최대 크기가 `80 × 1,000`이어서 길게 연결된 영역도 생길 수 있으므로 재귀 호출 대신 큐를 사용했다.

시간과 공간 복잡도는 $O(WH)$이다. 각 목장 칸은 큐에 한 번씩 들어간다. 원문 예제에서는 영역의 크기가 `4`, `16`, `6`이므로 답은 `16`이다.

## 5. 1194 — 호수찾기

[문제 원문](https://jungol.co.kr/problem/1194)

물이 있는 칸들이 상하좌우로 연결되면 하나의 호수가 된다. 가장 큰 호수의 면적을 구한다.

위성사진과 탐색 방식은 같다. 차이는 **격자 전체가 아니라 물이 있는 칸의 좌표 `K`개를 입력받는다**는 점이다. 먼저 좌표를 격자에 표시하면 같은 연결 요소 탐색을 적용할 수 있다.

```cpp showLineNumbers
void solve(){
    int n, m, k; ri(n, m, k);
    vvi a(n, vi(m));
    F0R(i, k){
        int x, y; ri(x, y);
        a[x - 1][y - 1] = 1;
    }

    int res = 0;
    F0R(r, n) F0R(c, m){
        if(a[r][c] == 0) continue;
        queue<pii> q;
        q.push({r, c});
        a[r][c] = 0;
        int cnt = 0;

        while(!q.empty()){
            auto [x, y] = q.front(); q.pop();
            ++cnt;
            F0R(d, 4){
                int nx = x + dx[d], ny = y + dy[d];
                if(!bound(nx, ny, n, m) || a[nx][ny] == 0) continue;
                a[nx][ny] = 0;
                q.push({nx, ny});
            }
        }
        chmax(res, cnt);
    }
    po(res);
}
```

시간 복잡도는 격자 초기화·순회와 좌표 입력을 합쳐 $O(NM + K)$, 공간 복잡도는 $O(NM)$이다. 원문 예제의 답은 `4`다.

원문의 입력 설명 첫 문장에는 물이 있는 칸 수가 `M`으로 적혀 있지만, 문제 정의와 다음 문장·예제에 따라 세 번째 입력값은 `K`로 읽는다. 좌표는 행, 열 순서이며 1부터 시작한다.

## 6. 1696 — 미로만들기

[문제 원문](https://jungol.co.kr/problem/1696)

왼쪽 위에서 오른쪽 아래로 이동하려고 한다. 흰 방은 그대로 지나갈 수 있고, 검은 방은 흰 방으로 바꿔야 한다. 최소화할 값은 이동 횟수가 아니라 **바꾸는 검은 방의 개수**다.

### 흰 방은 비용 0, 검은 방은 비용 1

다음 칸에 들어갈 때 흰 방이면 비용 `0`, 검은 방이면 비용 `1`을 더한다. 간선 비용이 0과 1뿐이므로 0-1 BFS를 사용할 수 있다.

- 비용 0으로 갱신한 상태는 덱의 앞에 넣는다.
- 비용 1로 갱신한 상태는 덱의 뒤에 넣는다.

일반 BFS처럼 처음 발견한 순간 방문을 확정하면 안 된다. 나중에 흰 방을 따라 돌아온 경로가 더 적은 비용으로 같은 칸에 도착할 수 있기 때문이다. `chmin`으로 비용이 실제로 줄어든 경우에만 덱에 추가한다.

```cpp showLineNumbers
void solve(){
    int n; ri(n);
    vs a(n); ri(a);
    vvl dist(n, vl(n, iinf));
    deque<tl3> q;
    dist[0][0] = 0;
    q.push_front({0, 0, 0});

    while(!q.empty()){
        auto [cost, x, y] = q.front(); q.pop_front();
        if(cost != dist[x][y]) continue;
        F0R(d, 4){
            int nx = x + dx[d], ny = y + dy[d];
            if(!bound(nx, ny, n, n)) continue;
            int w = (a[nx][ny] == '0');
            ll nd = cost + w;
            if(!chmin(dist[nx][ny], nd)) continue;
            if(w == 0) q.push_front({nd, nx, ny});
            else q.push_back({nd, nx, ny});
        }
    }
    po(dist[n - 1][n - 1]);
}
```

덱에는 삽입 시점의 비용도 같이 저장한다. 꺼냈을 때 현재 최솟값과 다르다면 이미 더 좋은 경로가 발견된 오래된 상태이므로 건너뛴다.

여기서 문자 `'0'`은 검은 방이고 `'1'`은 흰 방이다. 일반적인 벽 격자 문제와 표현을 혼동하기 쉽다. 시작 방과 끝 방은 흰 방이며, 변경 없이 도착할 수 있으면 답은 `0`이다. 원문 예제는 `2`다.

시간과 공간 복잡도는 $O(N^2)$이다. 칸을 정점으로 보고 상하좌우 이동을 간선으로 보면 정점과 간선 수가 모두 $O(N^2)$이다.

## 7. 1892 — 게임

[문제 원문](https://jungol.co.kr/problem/1892)

아무 칸에서나 출발해 상하좌우로 움직이되, 현재 값보다 **엄격하게 큰 값**이 있는 칸으로만 갈 수 있다. 최대 방문 칸 수를 구한다. 시작 칸도 방문한 칸에 포함한다.

### 값이 증가하므로 사이클이 없다

작은 값에서 큰 값으로 간선을 그리면 방향 그래프가 된다. 이동할 때마다 값이 증가하므로 다시 원래 칸으로 돌아올 수 없다. 즉, DAG다.

`dp[x][y]`를 `(x, y)`에서 끝나는 증가 경로의 최대 방문 칸 수로 정의한다. 모든 칸은 혼자서도 길이 1인 경로가 되므로 초기값은 `1`이다.

칸들을 값이 작은 순서로 처리하면, 현재 칸으로 들어올 수 있는 작은 값의 칸은 이미 처리되어 있다. 현재 값보다 큰 이웃의 DP를 `현재 DP + 1`로 갱신하면 된다.

```cpp showLineNumbers
void solve(){
    int n, m; ri(n, m);
    vvi a(n, vi(m)); ri(a);
    vector<ti3> order;
    F0R(x, n) F0R(y, m) order.pb({a[x][y], x, y});
    sort(all(order));

    vvi dp(n, vi(m, 1));
    int res = 1;
    for(auto [value, x, y] : order){
        chmax(res, dp[x][y]);
        F0R(d, 4){
            int nx = x + dx[d], ny = y + dy[d];
            if(!bound(nx, ny, n, m) || a[nx][ny] <= value) continue;
            chmax(dp[nx][ny], dp[x][y] + 1);
        }
    }
    po(res);
}
```

같은 값 사이에서는 이동할 수 없으므로, 정렬에서 같은 값의 칸들이 어떤 순서로 놓여도 결과는 같다. 재귀 DFS와 메모이제이션으로도 풀 수 있지만, 여기서는 긴 증가 경로에서도 재귀 깊이를 신경 쓰지 않도록 정렬 순서로 계산했다.

시간 복잡도는 정렬을 포함해 $O(NM\log(NM))$, 공간 복잡도는 $O(NM)$이다. 원문 예제는 1부터 25까지 나선 모양으로 이동할 수 있어 답이 `25`다. 모든 값이 같다면 이동할 수 없지만 시작 칸 하나는 방문하므로 답은 `1`이다.

## 방문 여부와 최적값을 구분하기

위성사진과 호수찾기는 영역에 속한 칸을 빠짐없이 세면 된다. 방문 여부만으로 충분하다. 장기는 이동 비용이 모두 같아서 첫 방문에 최단 거리를 확정할 수 있다.

하지만 미로만들기는 더 적은 비용의 재방문을 허용해야 한다. 경로찾기는 같은 칸이라도 이동 횟수까지 나누어야 한다. 해밀턴 순환회로는 방문한 장소 집합이 다음 선택을 바꾸고, 게임은 값이 증가한다는 조건이 계산 순서를 만들어 준다.

격자라는 모양보다 먼저 볼 것은 **최소화하거나 최대화할 값, 그리고 다음 이동을 제한하는 정보**다. 그 정보가 상태에 들어가야 필요한 경로를 실수로 버리지 않는다.
