각 코드 블록은 개인 템플릿의 `solve()`를 교체해서 사용한다. 공통 헤더, 자료형 별칭, 입출력 함수, `Main()`, `main()`은 생략했다. `Main()`의 `t = 1`은 그대로 둔다. 여러 입력을 받는 8893과 1748은 `solve()` 내부에서 종료 표식을 처리한다.

## 1. 8701 — 치매예방수칙 3.3.3

[문제 원문](https://jungol.co.kr/problem/8701)

길이 1,000 이하의 문자열에 1부터 1,000 사이의 정수가 들어 있다. 숫자는 `.`, `|`, `:`, `#` 중 하나로 구분되며, 모든 수의 합을 구하면 된다.

### 숫자를 읽는 동안만 현재 값을 유지하기

숫자 한 글자를 읽을 때마다 `cur = cur * 10 + digit`으로 값을 만든다. 숫자가 아닌 문자를 만나면 지금까지 읽은 수가 끝났으므로 합에 더하고 `cur`를 0으로 되돌린다. 구분자의 종류별로 분기할 필요는 없다.

문자열 끝에는 구분자가 없다는 점이 중요하다. 반복문이 끝난 후 마지막 `cur`를 한 번 더 더한다. 예를 들어 `123|456:789#999`는 `123 + 456 + 789 + 999 = 2367`이다.

```cpp showLineNumbers
void solve(){
    int n; string s;
    ri(n, s);
    ll res = 0, cur = 0;
    each(c, s){
        if('0' <= c && c <= '9') cur = cur * 10 + (c - '0');
        else { res += cur; cur = 0; }
    }
    po(res + cur);
}
```

시간 복잡도는 $O(N)$이다. 입력 문자열을 저장하는 공간은 $O(N)$이고, 계산에 추가로 필요한 공간은 $O(1)$이다.

## 2. 3136 — Tutorial : const구간의 합 구하기 (2D)

[문제 원문](https://jungol.co.kr/problem/3136)

값이 바뀌지 않는 최대 `1000 × 1000` 배열에서 직사각형 합을 최대 100만 번 묻는다. 매 질의마다 사각형 안을 순회하면 같은 원소를 계속 더하게 된다.

### 겹치는 영역을 한 번 되돌려 주기

`p[r][c]`를 `(1, 1)`부터 `(r, c)`까지의 합으로 두면 다음과 같이 만들 수 있다.

$$
p[r][c] = a[r][c] + p[r-1][c] + p[r][c-1] - p[r-1][c-1]
$$

위쪽과 왼쪽을 더할 때 왼쪽 위 영역이 두 번 포함되므로 한 번 뺀다. 질의에서도 같은 포함·배제 원리를 사용한다.

$$
sum = p[er][ec] - p[sr-1][ec] - p[er][sc-1] + p[sr-1][sc-1]
$$

0번 행과 0번 열을 0으로 두면 첫 행이나 첫 열에서 시작하는 질의도 같은 식으로 처리할 수 있다. 원소의 절댓값이 최대 100만이므로 전체 합의 절댓값은 $10^{12}$까지 커질 수 있다. 누적합은 `ll`로 저장해야 한다.

```cpp showLineNumbers
void solve(){
    int n; ri(n);
    vvl p(n + 1, vl(n + 1));
    FOR(r, 1, n + 1) FOR(c, 1, n + 1){
        ll x; ri(x);
        p[r][c] = x + p[r - 1][c] + p[r][c - 1] - p[r - 1][c - 1];
    }
    int q; ri(q);
    while(q--){
        int sr, sc, er, ec; ri(sr, sc, er, ec);
        po(p[er][ec] - p[sr - 1][ec] - p[er][sc - 1] + p[sr - 1][sc - 1]);
    }
}
```

전처리는 $O(N^2)$, 질의 한 번은 $O(1)$이므로 전체 시간은 $O(N^2 + Q)$이다. 공간은 $O(N^2)$이다. 음수가 들어 있어도 식은 그대로 성립한다.

## 3. 3101 — 요세푸스 문제 1

[문제 원문](https://jungol.co.kr/problem/3101)

사람이 최대 10,000명일 때 매번 $K$번째 사람을 제거한 순서 전체를 출력한다. 마지막 생존자만 구하는 점화식으로는 필요한 출력을 만들 수 없다.

### 사람의 번호와 남아 있는 순위를 구분하기

남아 있는 사람을 번호순으로 저장하고, 이번에 세기 시작할 위치를 0부터 세는 순위 `pos`로 관리한다. 사람이 `size`명 남았다면 제거할 순위는 다음과 같다.

$$
pos = (pos + K - 1) \bmod size
$$

제거 후에는 뒤에 있던 사람이 같은 순위로 당겨진다. 마지막 원소를 지운 경우도 다음 반복의 나머지 연산이 처음으로 돌려준다.

템플릿의 PBDS `ordered_set`은 `find_by_order(pos)`로 해당 순위의 원소를 찾을 수 있다. 각 사람을 실제로 $K$번씩 건너뛸 필요가 없다.

```cpp showLineNumbers
void solve(){
    int n, k; ri(n, k);
    ordered_set<int> alive;
    FOR(i, 1, n + 1) alive.insert(i);
    vi res;
    ll pos = 0;
    while(!alive.empty()){
        pos = (pos + k - 1) % len(alive);
        auto it = alive.find_by_order(pos);
        int who = *it;
        res.pb(who);
        alive.erase(who);
    }
    po(res);
}
```

탐색과 삭제가 각각 $O(\log N)$이므로 전체 시간은 $O(N\log N)$, 공간은 $O(N)$이다. `N = 5, K = 3`이면 `3 1 5 2 4`가 된다.

## 4. 8893 — Large 피보나치

[문제 원문](https://jungol.co.kr/problem/8893)

$N$이 $10^{18}$까지 주어지므로 첫 항부터 차례대로 더할 수 없다. 각 입력에 대해 $F_N \bmod (10^9 + 7)$을 출력하고, `-1`이 나오면 종료한다. `0`은 종료 표식이 아니라 답이 0인 정상 입력이다.

### 이웃한 두 항을 함께 구하기

`fib(n)`이 $(F_n, F_{n+1})$을 반환하도록 만들면, 절반 크기의 결과 $(a,b)=(F_m,F_{m+1})$로 다음 두 값을 구할 수 있다.

$$
F_{2m} = a(2b-a), \qquad F_{2m+1} = a^2+b^2
$$

짝수 `n`에서는 이 두 값을 그대로 반환하고, 홀수 `n`에서는 $(F_{2m+1}, F_{2m}+F_{2m+1})$을 반환한다. 이는 피보나치 덧셈 공식으로부터 얻는 빠른 두 배 계산이다. 매 단계에서 `n`을 절반으로 줄인다.

나머지 연산 중 `2b-a`가 음수가 될 수 있으므로 모듈러 값을 더해 보정한다. 곱셈 피연산자는 모두 나머지 범위에 있으며, `a*a + b*b`도 `ll` 범위 안이다.

```cpp showLineNumbers
void solve(){
    const ll mod = 1000000007;
    auto fib = [&](auto&& self, ll n) -> pll {
        if(n == 0) return {0, 1};
        auto [a, b] = self(self, n / 2);
        ll c = a * ((2 * b % mod - a + mod) % mod) % mod;
        ll d = (a * a + b * b) % mod;
        if(n & 1) return {d, (c + d) % mod};
        return {c, d};
    };
    ll n;
    while(cin >> n && n != -1) po(fib(fib, n).fi);
}
```

테스트 케이스마다 시간과 재귀 스택은 $O(\log(N+1))$이다. `N = 0`은 상수 시간에 처리한다. 입력은 최대 50개다.

## 5. 4207 — [swat]치킨배달

[문제 원문](https://jungol.co.kr/problem/4207)

제목은 치킨배달이지만 현재 정올 본문에서는 값이 2인 시설을 **전봇대**로 설명한다. 여기서는 본문의 용어를 따른다. 최대 13개 시설 중 최대 $M$개를 남겨, 각 집에서 가장 가까운 시설까지의 맨해튼 거리 합을 최소화한다.

### 최대 M개라면 정확히 M개를 골라도 된다

시설을 하나 더 남긴다고 집에서 가장 가까운 시설까지의 거리가 늘어나지는 않는다. 시설 수가 $M$ 이상이므로 정확히 $M$개를 선택하는 조합만 살펴봐도 최적해를 얻는다.

집이 $H$개, 시설이 $C$개라면 집과 시설 사이의 거리 $HC$개를 먼저 계산한다. 이후 조합마다 집별 최소 거리를 더한다. 시설 하나의 거리 합이 작다고 먼저 고르는 탐욕법은 집들의 담당 영역이 겹치는 효과를 반영하지 못한다.

```cpp showLineNumbers
void solve(){
    int n, m; ri(n, m);
    vp houses, facilities;
    F0R(r, n) F0R(c, n){
        int x; ri(x);
        if(x == 1) houses.pb({r, c});
        if(x == 2) facilities.pb({r, c});
    }
    int h = len(houses), c = len(facilities);
    vvi dist(h, vi(c));
    F0R(i, h) F0R(j, c){
        dist[i][j] = abs(houses[i].fi - facilities[j].fi)
                   + abs(houses[i].se - facilities[j].se);
    }
    vi picked;
    ll res = iinf;
    auto dfs = [&](auto&& self, int start) -> void {
        if(len(picked) == m){
            ll sum = 0;
            F0R(i, h){
                int best = INT_MAX;
                each(j, picked) chmin(best, dist[i][j]);
                sum += best;
            }
            chmin(res, sum);
            return;
        }
        int need = m - len(picked);
        FOR(j, start, c - need + 1){
            picked.pb(j);
            self(self, j + 1);
            picked.pop_back();
        }
    };
    dfs(dfs, 0);
    po(res);
}
```

시간은 $O(N^2 + HC + \binom{C}{M}HM)$, 공간은 $O(HC + H + C + M)$이다. 도시 배열 전체는 저장하지 않는다. 선택할 시설이 부족한 재귀 분기는 반복문의 끝 범위에서 제외한다.

## 6. 1462 — 보물섬

[문제 원문](https://jungol.co.kr/problem/1462)

상하좌우로 연결된 육지 사이에서, **최단 거리의 최댓값**을 구한다. 멀리 돌아가는 경로를 찾는 최장 경로 문제가 아니다.

### 시작점을 고정하면 BFS, 시작점을 모르면 모두 시도하기

한 육지를 시작점으로 정하면 BFS로 연결된 모든 육지까지의 최단 거리를 구할 수 있다. 이를 모든 육지에 대해 반복하고, 발견한 거리 중 가장 큰 값을 답으로 사용한다.

격자에는 사이클이 있을 수 있다. 트리의 지름을 구할 때 쓰는 두 번의 BFS만으로는 일반 그래프의 지름이 항상 구해지지 않는다. 가로·세로가 각각 최대 50이므로 모든 시작점을 확인해도 충분하다.

```cpp showLineNumbers
void solve(){
    int n, m; ri(n, m);
    vs a(n); ri(a);
    int res = 0;
    F0R(sr, n) F0R(sc, m){
        if(a[sr][sc] != 'L') continue;
        vvi dist(n, vi(m, -1));
        queue<pii> q;
        dist[sr][sc] = 0;
        q.push({sr, sc});
        while(!q.empty()){
            auto [r, c] = q.front(); q.pop();
            chmax(res, dist[r][c]);
            F0R(dir, 4){
                int nr = r + dx[dir], nc = c + dy[dir];
                if(!bound(nr, nc, n, m) || a[nr][nc] != 'L') continue;
                if(dist[nr][nc] != -1) continue;
                dist[nr][nc] = dist[r][c] + 1;
                q.push({nr, nc});
            }
        }
    }
    po(res);
}
```

육지 수를 $L$이라고 하면 시간은 $O(LNM)$, 공간은 $O(NM)$이다. 방문 여부는 큐에 넣을 때 기록해 같은 칸이 중복 삽입되지 않도록 한다. 서로 다른 섬 사이의 도달 불가능한 거리는 비교 대상에서 제외된다.

## 7. 12007 — 나이트의 이동2

[문제 원문](https://jungol.co.kr/problem/12007)

체스판의 각 변은 최대 100,000이지만 이동 횟수 $K$는 최대 100이다. 원하는 값은 **정확히 K번 이동해서 도착할 수 없는 칸의 수**다. 같은 칸을 다시 방문해도 된다.

### 전체 판 대신 시작점 주변만 탐색하기

한 번 움직일 때 각 좌표는 최대 2만큼 변한다. 따라서 $K$번 이내에 도착하는 칸은 시작점에서 각 축으로 $2K$ 이내에 있다. 이 범위를 원래 체스판과 교차시키면 탐색할 사각형은 최대 `(4K + 1) × (4K + 1)`이다.

이 사각형 안에서 깊이 $K$까지만 BFS를 수행해 최단 거리 `d`를 구한다. 어떤 길이 $K$ 이하의 경로도 사각형 밖을 나갈 수 없으므로 필요한 경로가 잘리지 않는다.

### 최단 거리에서 정확한 이동 횟수로 바꾸기

나이트는 이동할 때마다 칸 색을 바꾼다. 따라서 도착 가능하려면 `d <= K`이면서 `K - d`가 짝수여야 한다. 이 조건은 시작점이 고립되지 않았다면 충분하기도 하다. 경로 중 한 간선을 갔다가 돌아오면 이동 횟수를 2씩 늘릴 수 있기 때문이다.

예외는 시작점에서 한 번도 움직일 수 없는 경우다. `d = 0`이라는 이유만으로 짝수 번 이동 후 시작점에 돌아올 수 있다고 세면 안 된다. 원문의 $K$는 1 이상이므로 이 경우 도착 가능한 칸은 없다.

```cpp showLineNumbers
void solve(){
    int n, m, x, y, k; ri(n, m, x, y, k);
    --x; --y;
    int top = max(0, x - 2 * k), bottom = min(n - 1, x + 2 * k);
    int left = max(0, y - 2 * k), right = min(m - 1, y + 2 * k);
    int h = bottom - top + 1, w = right - left + 1;
    int sx = x - top, sy = y - left;
    bool movable = false;
    F0R(dir, 8) if(bound(x + knx[dir], y + kny[dir], n, m)) movable = true;

    vvi dist(h, vi(w, -1));
    queue<pii> q;
    dist[sx][sy] = 0;
    q.push({sx, sy});
    ll reachable = 0;
    while(!q.empty()){
        auto [r, c] = q.front(); q.pop();
        int d = dist[r][c];
        if((k - d) % 2 == 0 && (d > 0 || k == 0 || movable)) ++reachable;
        if(d == k) continue;
        F0R(dir, 8){
            int nr = r + knx[dir], nc = c + kny[dir];
            if(!bound(nr, nc, h, w) || dist[nr][nc] != -1) continue;
            dist[nr][nc] = d + 1;
            q.push({nr, nc});
        }
    }
    po(1LL * n * m - reachable);
}
```

시간과 공간 모두 $O(K^2)$이다. 실제로는 원래 체스판의 경계에 따라 더 작아진다. 전체 칸 수는 최대 $10^{10}$이므로 곱셈부터 `ll`로 계산한다.

## 8. 1111 — 등산로 찾기

[문제 원문](https://jungol.co.kr/problem/1111)

산 바깥의 높이는 0이며 어느 바깥 위치에서든 출발할 수 있다. 같은 높이로 이동하면 비용 0, 내려가면 높이 차, 올라가면 높이 차의 제곱만큼 힘이 든다. 목표 좌표는 입력으로 주어진다.

### 바깥을 가상의 출발점으로 생각하기

모든 경계 칸 `(r, c)`에 대해 바깥 높이 0에서 진입하는 비용 `height[r][c]²`을 초기 거리로 넣는다. 하나의 가상 출발점이 각 경계 칸으로 이어지는 것과 같다.

경로가 산을 나갔다가 다시 들어오는 경우를 따로 탐색할 필요도 없다. 마지막으로 들어오는 경계에서 새로 출발하면 그 이전의 음수 아닌 비용을 없앨 수 있다.

이후 이동 비용이 모두 0 이상인 그래프에서 다익스트라를 수행한다. 오르막과 내리막 비용이 다르므로 **좌표가 인접하더라도 두 방향의 간선 비용은 다르다**. 높이 차 `diff = next - current`에 대해 양수이면 제곱, 나머지는 `-diff`를 사용한다.

```cpp showLineNumbers
void solve(){
    int n, tr, tc; ri(n, tr, tc);
    --tr; --tc;
    vvi a(n, vi(n)); ri(a);
    vvl dist(n, vl(n, iinf));
    minpq<tl3> pq;
    F0R(r, n) F0R(c, n){
        if(r == 0 || c == 0 || r == n - 1 || c == n - 1){
            dist[r][c] = 1LL * a[r][c] * a[r][c];
            pq.push({dist[r][c], r, c});
        }
    }
    while(!pq.empty()){
        auto [cost, rr, cc] = pq.top(); pq.pop();
        int r = rr, c = cc;
        if(cost != dist[r][c]) continue;
        if(r == tr && c == tc){ po(cost); return; }
        F0R(dir, 4){
            int nr = r + dx[dir], nc = c + dy[dir];
            if(!bound(nr, nc, n, n)) continue;
            ll diff = a[nr][nc] - a[r][c];
            ll w = diff > 0 ? diff * diff : -diff;
            if(chmin(dist[nr][nc], cost + w)) pq.push({dist[nr][nc], nr, nc});
        }
    }
}
```

각 칸에서 간선이 최대 4개이므로 시간은 $O(N^2\log(N^2))$, 공간은 $O(N^2)$이다. 원문 예제의 답 8에는 바깥에서 높이 2인 칸으로 올라가는 비용 4도 포함된다.

## 9. 8699 — 무등산 등반

[문제 원문](https://jungol.co.kr/problem/8699)

이번에는 출발점이 하나로 고정되어 있고, 지도에서 유일하게 가장 높은 칸이 목적지다. 높이 차가 $c$를 넘으면 이동할 수 없다. 평지는 1분, 오르막은 높이 차에 $a$를 곱한 시간, 내리막은 높이 차에 $b$를 곱한 시간이 든다.

### 이동 가능한지 먼저 판단하고 비용을 계산하기

1111번과 비슷해 보이지만 평지의 비용, 오르막 공식, 시작 조건이 모두 다르다. 먼저 `abs(diff) > c`인 이동을 제외하고, 남은 이동에만 방향별 비용을 부여한다.

최대 `500 × 500` 격자에서 양수 가중치 최단 경로를 구하므로 우선순위 큐를 사용하는 다익스트라가 맞는다. 개선된 거리만 큐에 넣고, 꺼낸 거리와 현재 최단 거리가 다르면 오래된 항목이므로 건너뛴다.

```cpp showLineNumbers
void solve(){
    int n, m, sx, sy, up, down, limit;
    ri(n, m, sx, sy, up, down, limit);
    --sx; --sy;
    vvi a(n, vi(m)); ri(a);
    int tr = 0, tc = 0;
    F0R(r, n) F0R(c, m) if(a[r][c] > a[tr][tc]) { tr = r; tc = c; }
    vvl dist(n, vl(m, iinf));
    minpq<tl3> pq;
    dist[sx][sy] = 0;
    pq.push({0, sx, sy});
    while(!pq.empty()){
        auto [cost, rr, cc] = pq.top(); pq.pop();
        int r = rr, c = cc;
        if(cost != dist[r][c]) continue;
        if(r == tr && c == tc){ po(cost); return; }
        F0R(dir, 4){
            int nr = r + dx[dir], nc = c + dy[dir];
            if(!bound(nr, nc, n, m)) continue;
            int diff = a[nr][nc] - a[r][c];
            if(abs(diff) > limit) continue;
            ll w = diff == 0 ? 1 : (diff > 0 ? 1LL * up * diff : -1LL * down * diff);
            if(chmin(dist[nr][nc], cost + w)) pq.push({dist[nr][nc], nr, nc});
        }
    }
    po(-1);
}
```

시간은 $O(NM\log(NM))$, 공간은 $O(NM)$이다. 도달할 수 없다면 원문의 요구대로 `-1`을 출력한다. 최종 답이 32비트 정수 범위에 들어가더라도 후보 경로의 누적 비용 계산을 안전하게 하기 위해 `ll`을 쓴다.

제공된 기록에는 제출 `13953461`의 시간 초과 이후 `13953465`의 100점 정답이 있다. 다만 실제 두 코드의 차이는 확인하지 못했다. 위 예시는 그 수정 과정을 재현한 코드가 아니다. 이 문제에서 일반적으로 점검할 부분은 **거리가 개선될 때만 큐에 넣는지**, **오래된 큐 항목을 건너뛰는지**다.

## 10. 1855 — 모이기

[문제 원문](https://jungol.co.kr/problem/1855)

최대 500명의 학생이 최대 800개 장소에 살고 있다. 양방향 경로는 최대 1,450개다. 모든 학생이 한 장소로 모이는 데 걸리는 **이동 시간의 합**을 최소화한다. 같은 장소에 여러 학생이 살 수 있다.

### 같은 출발지의 최단 거리는 한 번만 구하기

장소 `s`에 사는 학생 수를 `count[s]`로 모은다. 학생이 있는 서로 다른 출발지에서만 다익스트라를 수행하고, 각 모임 후보 `v`에 다음 값을 누적한다.

$$
total[v] = \sum_s count[s]\cdot dist(s,v)
$$

최적의 모임 장소가 학생이 사는 곳일 필요는 없다. 출발지는 묶어도 모임 후보는 모든 장소로 유지해야 한다. 또한 도달하지 못하는 학생이 있는 장소는 후보에서 제외한다.

```cpp showLineNumbers
void solve(){
    int n, p, c; ri(n, p, c);
    vector<vp> g(p);
    F0R(i, c){
        int u, v, w; ri(u, v, w); --u; --v;
        g[u].pb({v, w}); g[v].pb({u, w});
    }
    vi count(p);
    F0R(i, n){ int x; ri(x); ++count[x - 1]; }
    vl total(p);
    vi reached(p);
    F0R(s, p){
        if(count[s] == 0) continue;
        vl dist(p, iinf);
        minpq<pll> pq;
        dist[s] = 0; pq.push({0, s});
        while(!pq.empty()){
            auto [cost, uu] = pq.top(); pq.pop();
            int u = uu;
            if(cost != dist[u]) continue;
            each(edge, g[u]){
                auto [v, w] = edge;
                if(chmin(dist[v], cost + w)) pq.push({dist[v], v});
            }
        }
        F0R(v, p) if(dist[v] != iinf){
            total[v] += dist[v] * count[s];
            reached[v] += count[s];
        }
    }
    ll res = iinf;
    F0R(v, p) if(reached[v] == n) chmin(res, total[v]);
    po(res == iinf ? -1 : res);
}
```

학생이 있는 서로 다른 장소 수를 $U$라 하면, 시간은 $O(U(P+C)\log(P+1))$, 공간은 $O(P+C)$이다. 모든 출발지의 거리 행렬을 저장할 필요는 없다.

원문은 모두 모일 수 없는 입력의 출력값을 따로 명시하지 않는다. 예시의 `-1`은 그런 입력에 대한 자체 방어 처리이며 공식 출력 규칙으로 주장하지 않는다.

## 11. 1748 — 주식거래자

[문제 원문](https://jungol.co.kr/problem/1748)

한 사람에게 처음 정보를 주었을 때, 정보가 모든 사람에게 전달되는 시간을 최소화한다. 거래자가 최대 100명이므로 플로이드–워셜로 모든 쌍 최단 거리를 구할 수 있다. 입력은 여러 케이스이며 거래자 수 `0`에서 끝난다.

### 합이 아니라 마지막 도착 시간을 비교하기

입력에서 `u`번째 줄의 `(v, w)`는 `u → v`로 정보를 전달하는 데 `w`가 걸린다는 뜻이다. 양방향으로 추가하면 안 된다.

정보는 여러 경로로 퍼질 수 있으므로 출발자가 `s`일 때 전체 전파 완료 시간은 거리의 합이 아니라 가장 늦게 도착하는 사람까지의 거리다.

$$
finish(s)=\max_v dist(s,v), \qquad answer=\min_s finish(s)
$$

한 명이라도 도달할 수 없으면 그 출발자는 제외한다. 가능한 출발자가 전혀 없을 때만 `disjoint`를 출력한다. 그래프가 강하게 연결되어 있지 않아도 특정 한 사람에게서 모두에게 도달할 수 있다면 답이 존재한다.

```cpp showLineNumbers
void solve(){
    int n;
    while(cin >> n && n != 0){
        vvl dist(n, vl(n, iinf));
        F0R(i, n) dist[i][i] = 0;
        F0R(u, n){
            int cnt; ri(cnt);
            while(cnt--){
                int v, w; ri(v, w); --v;
                chmin(dist[u][v], w);
            }
        }
        F0R(k, n) F0R(u, n){
            if(dist[u][k] == iinf) continue;
            F0R(v, n){
                if(dist[k][v] == iinf) continue;
                chmin(dist[u][v], dist[u][k] + dist[k][v]);
            }
        }
        int who = -1;
        ll best = iinf;
        F0R(u, n){
            ll finish = *max_element(all(dist[u]));
            if(chmin(best, finish)) who = u;
        }
        if(who == -1) po("disjoint");
        else po(who + 1, best);
    }
}
```

케이스마다 시간은 $O(N^3)$, 공간은 $O(N^2)$이다. 완료 시간이 같으면 위 코드는 작은 번호를 유지한다. 원문은 동률 처리 규칙을 별도로 적지 않았으며, 이는 예시 코드의 일관된 선택 기준이다.

## 12. 26276 — 입소문의 힘

[문제 원문](https://jungol.co.kr/problem/26276)

양방향 친구 관계마다 신뢰도가 있다. 신뢰도가 기준 $K$ 이상인 관계만 사용할 때 시작 학생에서 목표 학생으로 전달할 수 있는 가장 큰 $K$를 구한다. 학생은 최대 10,000명, 관계는 최대 500,000개이며 두 학생 사이의 경로는 항상 존재한다.

### 경로의 합 대신 가장 약한 간선을 관리하기

한 경로에서 허용할 수 있는 기준은 그 경로에 포함된 **최소 신뢰도**다. 따라서 필요한 값은 다음과 같다.

$$
\max_{\text{path }S\to E}\;\min_{e\in\text{path}} w_e
$$

`best[u]`를 시작점에서 `u`까지 확보한 최대 기준으로 정의한다. 신뢰도 `w`인 간선으로 `v`까지 확장하면 새 경로의 기준은 `min(best[u], w)`이다. 이 값이 기존 `best[v]`보다 클 때 갱신한다.

경로에 간선을 붙여도 그 경로의 최소 신뢰도는 커질 수 없다. 따라서 현재 기준이 가장 큰 정점부터 확정하는 다익스트라 변형을 쓸 수 있다. 보통의 최단 경로와 달리 최대 힙을 사용한다.

```cpp showLineNumbers
void solve(){
    int n, m; ri(n, m);
    vector<vp> g(n);
    F0R(i, m){
        int u, v, w; ri(u, v, w); --u; --v;
        g[u].pb({v, w}); g[v].pb({u, w});
    }
    int s, e; ri(s, e); --s; --e;
    vi best(n, -1);
    maxpq<pii> pq;
    best[s] = INT_MAX;
    pq.push({best[s], s});
    while(!pq.empty()){
        auto [value, u] = pq.top(); pq.pop();
        if(value != best[u]) continue;
        if(u == e){ po(value); return; }
        each(edge, g[u]){
            auto [v, w] = edge;
            int candidate = min(value, w);
            if(chmax(best[v], candidate)) pq.push({candidate, v});
        }
    }
}
```

단순 무방향 그래프에서 시간은 $O((N+M)\log N)$, 공간은 $O(N+M)$이다. 시작점의 `INT_MAX`는 아직 간선을 지나지 않아 신뢰도 제한이 없다는 의미다. 원문은 시작점과 목표점이 서로 다름을 보장한다.

기준을 고정한 뒤 BFS로 도달 가능성을 확인하는 이분 탐색 풀이도 가능하다. 다만 위 방식은 현재까지 확보한 기준을 직접 갱신하므로 별도의 기준 탐색이 필요 없다.

## 문제마다 달랐던 판단 기준

같은 그래프 탐색이어도 무엇을 최적화하는지는 다르다. 1855번은 학생들의 거리 **합**, 1748번은 마지막 사람까지의 거리 **최댓값**, 26276번은 경로의 **최소 간선 값**을 비교한다. 우선순위 큐나 최단 경로 알고리즘을 고르기 전에 먼저 답의 식을 써 두는 편이 도움이 된다.

입력 크기도 그대로 탐색 크기가 되는 것은 아니다. 12007번은 체스판 전체가 거대해도 이동 횟수로 탐색 범위를 제한할 수 있고, 4207번은 도시 크기보다 선택할 시설 수가 조합 탐색의 규모를 결정한다. 반대로 1462번은 일반 그래프에서 성립하지 않는 지름 최적화를 억지로 쓰기보다, 허용되는 크기 안에서 모든 시작점을 확인하는 편이 명확하다.
